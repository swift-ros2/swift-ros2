# API breakages intentionally introduced after the baseline release.
#
# CI (ci.yml, "Check (API stability vs latest release)") resolves the baseline
# dynamically: the highest stable 3.x tag, or, until 3.0.0 exists, the newest
# 3.0.0-rc.* tag. It runs `swift package diagnose-api-breaking-changes` against
# that tag, so a removal of an API that an earlier release or candidate of the
# 3.x line already shipped is caught.
#
# Each line below is matched verbatim against a diagnostic message; comments
# and blank lines are ignored. Append entries when intentional breakages land
# during a release cycle; drop them again once a tag is cut whose baseline
# already includes them (the baseline moves on every release candidate, so an
# entry for a change that is already in the baseline matches nothing).
#
# Removals of public APIs are SemVer-breaking: once 3.0.0 is tagged, adding an
# entry here is a signal that a major version bump is required. The one
# exception is a new `ROS2Distro` case for a new ROS 2 release: by policy
# (README "API stability", MIGRATION "2.0 → 2.1") it ships in a minor.
#
# NOTE: this gate does not catch a `public` -> `package` demotion (SwiftPM's
# ABI digest lists `package` declarations too, so a symbol that drops from
# `public` to `package` — while still present in the digest — is not reported
# as a breakage).
