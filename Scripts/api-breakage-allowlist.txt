# API breakages intentionally introduced after the latest released tag.
#
# CI resolves the baseline dynamically — the highest stable semver tag in the
# repo (e.g. `2.2.0` today, `2.3.0` once 2.3 ships) — and runs
# `swift package diagnose-api-breaking-changes` against it. That way removals
# of APIs added on the 2.x line (e.g. a symbol introduced in 2.1.0 then
# deleted before 2.2.0) are still caught — they would not have been if the
# baseline stayed pinned to 2.0.0 forever.
#
# Each line below is matched verbatim against a diagnostic message; comments
# and blank lines are ignored. Append entries when intentional breakages land
# during a release cycle; drop them again once a tag is cut whose baseline
# already includes them.
#
# Removals of public APIs are SemVer-breaking on the 2.x line — adding an
# entry here is a signal that a 3.0 bump is required. The one exception is a
# new `ROS2Distro` case for a new ROS 2 release: by policy (README "API
# stability", MIGRATION "2.0 → 2.1") it ships in a minor.
#
# NOTE: this gate does not catch a `public` -> `package` demotion (SwiftPM's
# ABI digest lists `package` declarations too, so a symbol that drops from
# `public` to `package` — while still present in the digest — is not reported
# as a breakage).

# `ZenohClientProtocol` is a `package` protocol (SwiftPM's digest includes package declarations), so public SemVer is unaffected; the entry drops after the 2.3.0 tag.
